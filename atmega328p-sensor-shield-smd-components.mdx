The sensor you want for a project is often sold in one form only: a square of plastic 2.5 mm wide with no legs at all. Most modern sensors are made this way, as surface-mount devices (SMD) that are soldered flat on the copper and need no holes. With through-hole design alone, you cannot use them. In this lesson you design a board that reads temperature, humidity and light with two such sensors and an ATmega328P in a surface-mount package. You learn how surface-mount footprints differ, how to solder them by hand, and how to cut the board on a CNC milling machine. #KiCad #SMD #SensorShield

## SMD Footprint Fundamentals

<InArticleAd />


A surface-mount part has no holes to guide it. Its footprint must match it to a tenth of a millimetre, so first learn how the sizes are named.

### Package Sizes

Surface-mount resistors and capacitors come in standard sizes. The name is the length and width in hundredths of an inch, not in millimetres: 0805 is 0.08 inch by 0.05 inch, which is 2.0 mm by 1.25 mm.

| Package | Size (mm) | Hand Solderable? | Use Case |
|---------|-----------|------------------|----------|
| 1206 | 3.2 x 1.6 | Easy | Prototypes, power resistors |
| 0805 | 2.0 x 1.25 | Comfortable | General purpose (this lesson) |
| 0603 | 1.6 x 0.8 | Moderate | Space-constrained designs |
| 0402 | 1.0 x 0.5 | Difficult | Professional assembly only |

### TQFP vs DIP

The ATmega328P-AU is the same chip as the 28-pin through-hole ATmega328P, in a flat square package 7 mm wide called TQFP-32. The distance from one pin to the next (the pitch) falls from 2.54mm to 0.8mm. Three things follow:

- The gap between two pads is about 0.25mm. No track can pass between two pads, and a track that leaves a pad must be narrower than the pad.
- A soldering iron alone bridges the pins easily. Solder paste and hot air work better.
- The package has four more pins: one more VCC, one more GND, and two inputs that are analog only (ADC6 and ADC7). So the pin numbers differ from the through-hole chip.

### Pad and Courtyard

Every surface-mount footprint in KiCad has three outlines:

- **Pads**: the copper areas where solder joins the part to the board
- **Courtyard**: the space the part needs around it, for the soldering tool and for the tolerance of placement
- **Fab layer**: the true outline of the part's body

Keep the courtyards of two parts from overlapping. The design rules check (DRC) reports it if they do.

### Power Supply

USB gives 5 V, which suits the MCU. The light sensor works only up to 3.6 V, so the sensors need their own 3.3 V supply. A small linear regulator (an LDO, low-dropout regulator) makes 3.3 V from the 5 V.

<Steps>
1. **Place the USB Micro-B connector.** Add `USB_B_Micro` from the Connector library. Only its 5 V pin (VBUS) and its ground pin are used.

2. **Place the 3.3V regulator.** Add `AMS1117-3.3` (SOT-223 package). Its input goes to the USB 5 V and its output to a `+3V3` power symbol.

3. **Add its two capacitors.** Place C7 (10 µF) from the regulator input to `GND` and C8 (10 µF) from the regulator output to `GND`. Without a capacitor at its output this regulator can oscillate.

4. **Add power symbols and wires.** USB VBUS to `+5V`, USB GND to `GND`, regulator input to `+5V`, regulator output to `+3V3`.
</Steps>

### MCU and Crystal

The MCU needs the same four circuits as on the [through-hole breakout board](/education/pcb-design-kicad/atmega328p-breakout-board-through-hole/): decoupling capacitors, a crystal as its clock, a reset pull-up, and a programming header.

<Steps>
1. **Place the ATmega328P-AU.** Add `ATmega328P-A`, the TQFP-32 symbol, in the center of the sheet.

2. **Connect power.** Wire VCC (pins 4 and 6) and AVCC (pin 18) to `+5V`. Wire GND (pins 3, 5, 21) to `GND`. Place 100 nF decoupling capacitors (C3, C4) at VCC and AVCC.

3. **Crystal circuit.** Place a `Crystal_GND24` (16 MHz, the 4-pin SMD crystal symbol, with its two case pins wired to GND) between XTAL1 (pin 7) and XTAL2 (pin 8). Add 22 pF load capacitors (C1, C2) from each crystal pin to GND.

4. **Reset circuit.** Connect a 10 kΩ pull-up (R1) from RESET (pin 29) to `+5V`. Add the SMD tactile switch from RESET to GND.

5. **ISP header.** Place `AVR-ISP-6` and wire MISO (PB4), MOSI (PB3), SCK (PB5), RESET, VCC and GND.
</Steps>

### I2C Bus and Sensors

I2C is a bus of two wires that many chips share: SDA carries the data and SCL the clock. A chip can only pull a wire down to 0 V, as a hand pulls a rope; nothing drives it up, so each wire needs one resistor to the supply (a pull-up) to return it high. Each sensor has its own address, so the MCU speaks to one at a time.

<Steps>
1. **I2C pull-ups.** Add two 4.7 kΩ resistors: R2 from SDA (PC4/pin 27) to `+3V3` and R3 from SCL (PC5/pin 28) to `+3V3`. A larger value lets the wire rise too slowly, and a much smaller one stops the chips pulling it low. The resistors go to 3.3V so the sensors never see 5 V. The ATmega328P at 5 V reads 3.3 V as high in practice, but its data sheet guarantees this only from 3.5 V, so a product would add a level shifter.

2. **Place the SHT30** (temperature and humidity). Add `SHT30-DIS`, or draw a symbol with VDD, GND, SDA, SCL, ADDR and ALERT pins. Connect VDD to `+3V3`, GND to `GND`, SDA and SCL to the bus. Connect ADDR to GND, which sets the address to 0x44. Add a 100 nF decoupling capacitor (C5).

3. **Place the VEML7700** (light). KiCad 9 has no symbol for it, so draw one in the Symbol Editor with VDD, GND, SDA and SCL pins. Connect VDD to `+3V3`, GND to `GND`, SDA and SCL to the bus. Its address is fixed at 0x10. Add a 100 nF decoupling capacitor (C6).
</Steps>

### UART Output

The board has no display, so it sends its readings as text over two serial wires (UART) to a USB-serial adapter on a computer.

<Steps>
1. **Place a 1x4 pin header** (J3) with the pins VCC, TX, RX, GND.

2. **Wire UART.** Connect ATmega328P TXD (PD1/pin 31) to the TX pin and RXD (PD0/pin 30) to the RX pin on the header.
</Steps>

### Power LED

<Steps>
1. **Place an 0805 LED** (D1) and a 330 Ω resistor (R4). Connect `+3V3` to R4, R4 to the D1 anode, and the D1 cathode to GND. The LED shows that the 3.3V supply is present.

2. **Run the electrical rules check (ERC)** and correct every error.
</Steps>

## PCB Layout

<InArticleAd />


### Board Setup

<Steps>
1. **Board outline.** On the Edge.Cuts layer, draw a 40 x 35 mm rectangle.

2. **Layer setup.** The board has copper on two faces: F.Cu (front) and B.Cu (back). Open **Board Setup > Board Stackup > Physical Stackup** and check that it shows two copper layers on a 1.6mm board.

3. **Design rules.** These are the limits KiCad holds you to while you route. Set the Default net class:
   - Track width: 0.25 mm. A track must be narrower than the TQFP pad it leaves, and a milling machine can still cut this width cleanly.
   - Clearance: 0.2 mm. The gap between two TQFP pads is about 0.25 mm, so a larger clearance would make every pin of the chip an error.
   - Via size: 0.6 mm, drill 0.3 mm

   Add a Power net class for `+5V`, `+3V3` and `GND`:
   - Track width: 0.5 mm. Supply tracks carry the current of the whole board, and a wider track loses less voltage.
   - Clearance: 0.2 mm
</Steps>

### Import and Place Components

<Steps>
1. **Update PCB from schematic** (F8). All footprints appear in one group.

2. **Place the USB connector** at the middle of the top edge, with its opening a little beyond the board edge so the plug can enter.

3. **Place U2 (the regulator)** near the USB connector, with C7 and C8 against its input and output pins.

4. **Place U1 (ATmega328P-AU)** in the center.

5. **Place the crystal** (Y1) as close to pins 7 and 8 as possible, with C1 and C2 beside it. A long track here picks up noise and can stop the clock.

6. **Place the decoupling capacitors** (C3, C4) within 3mm of the VCC and AVCC pins. Each millimetre of track weakens them.

7. **Place the sensors.** A temperature sensor reports its own temperature, and copper carries heat to it. Put U3 (SHT30) as far as you can from the regulator and the MCU, which are the warm parts. Put U4 (VEML7700) near a board edge where light reaches it.

8. **Place the ISP header** (J2) and the UART header (J3) on the bottom edge, where a cable can reach them.

9. **Place the reset button** near a board edge.
</Steps>

### Double-Sided Layout Tips

<Card title="SMD Placement Rules" icon="information">
- Keep all surface-mount parts on the front face, so they can be soldered with hot air in one pass
- Through-hole parts (the ISP and UART headers) can go on either face
- If a part must go on the back, press `F` to move it there
- The sensors must face the open air, not a surface the board is mounted on
</Card>

### Routing Strategy

<Steps>
1. **Route the supply tracks first** with the Power net class (0.5mm). Run +5V and +3V3 by the shortest path from their source to each part.

2. **Route the crystal.** Keep XTAL1 and XTAL2 short and of equal length, with no other signal beside them.

3. **Route the I2C bus.** SDA and SCL run from the MCU to both sensors and to the pull-up resistors. Keep each under 50mm. A longer track adds capacitance, and capacitance slows the rise of the signal.

4. **Route UART and ISP.** TX and RX to the UART header, then MISO, MOSI, SCK and RESET to the ISP header. These signals are slow and tolerate any reasonable path.

5. **Use vias where a track must cross another.** Press `V` while routing to place a via and continue on the other layer. Each via on a milled board must later be joined by hand, so use few (fewer than 20 on this board).

6. **Add ground pours on both layers.** Draw a GND zone on F.Cu and on B.Cu and fill them with `B` (Fill All Zones). The pour gives every part a short path to ground, and it leaves less copper for the mill to remove.

7. **Run DRC.** Correct it until there are no errors and no unconnected items.
</Steps>

### Optional: Speed Up With Freerouting

KiCad has no automatic router. **Freerouting** is a free program that routes a board for you. On a board this small, routing by hand teaches more. If you try it:

<Steps>
1. **Route the supply nets, the crystal and the I2C bus by hand and lock them.** Select each track and check **Locked** in the Properties panel.

2. **Install Freerouting** from [github.com/freerouting/freerouting](https://github.com/freerouting/freerouting) (it needs a Java runtime), or through KiCad's **Plugin and Content Manager**.

3. **Start it from the PCB Editor toolbar.** It routes the open board and returns the result to KiCad.

4. **Examine the result,** route again by hand any net with many vias, and run DRC again.
</Steps>

## Manufacturing: CNC Milling

<InArticleAd />


A CNC milling machine cuts a narrow channel around every pad and track, so each is left as an island of copper. To make a two-layer board, you mill one face, turn the board over and mill the other.

### Why CNC Milling?

It needs no chemicals, it drills the holes in the same setup, and it cuts channels of 0.1mm, fine enough for TQFP pads.

### CNC Milling Workflow

<Steps>
1. **Export Gerber files.** A Gerber file is a flat picture of one layer, in a format that board factories and milling programs read. In the KiCad PCB Editor, go to **File > Plot**. Select the `F.Cu`, `B.Cu` and `Edge.Cuts` layers. Set the format to **Gerber** and click **Plot**. Then click **Generate Drill Files** and choose Excellon format, which lists every hole.

2. **Turn the Gerbers into machine instructions (G-code).** **FlatCAM** (free) reads Gerbers and writes G-code. A sender program such as **Candle** or **bCNC** then passes the G-code to the machine.

3. **Set the milling values in FlatCAM:**
   - Tool: a V-shaped bit with a 0.1mm tip and a 30-degree angle
   - Isolation width: 0.15mm, with 2 or 3 passes for a wider channel
   - Feed rate: 100-200 mm/min
   - Cut depth: 0.05-0.1mm. The copper is only 0.035 mm thick, so this just passes through it.

4. **Fix the copper board** to the machine bed with double-sided tape. The board must lie flat: where it lifts, the cut is too deep, and where it sinks, copper remains.

5. **Set the tool height (the Z origin).** Lower the bit until it just touches the copper; a touch probe finds this point exactly. This setting decides the result: too high leaves copper between tracks, and too low lets the V-shaped bit cut a wide channel that eats the tracks.

6. **Mill the front copper.** Run the G-code for F.Cu.

7. **Drill the holes.** Change to a 0.8mm drill and run the drill file. Two of the holes will line up the second face.

8. **Turn the board over** on two pins through two drilled holes. Fix it and set the tool height again.

9. **Mill the back copper.** Run the G-code for B.Cu.

10. **Cut the outline.** Change to a 1-2mm end mill and run the G-code for Edge.Cuts.

11. **Clean and inspect.** Brush away the copper dust. With a magnifier, check that every channel is clean and no copper bridges two pads.
</Steps>

:::caution[The two faces must line up]
If the board moves by 0.5mm when you turn it over, the vias miss their pads on the second face. Always turn the board on pins through drilled holes, never by eye.
:::

### Connecting Front and Back Layers (Manual Vias)

A factory coats the inside of each hole with copper. A milled board has bare holes, so a via joins nothing until you put a wire through it:

<Steps>
1. Push a short piece of bare copper wire (0.5mm diameter) through the via hole.

2. Solder the wire to the pad on the front, then turn the board and solder it to the pad on the back.

3. Cut the wire flush with both joints.
</Steps>

## Soldering SMD Components

<InArticleAd />


These parts need other tools than through-hole parts.

### Tools Needed

| Tool | Purpose |
|------|---------|
| Fine-tip soldering iron (0.5mm tip) | Resistors, capacitors, LED, headers |
| Solder paste (Sn63/Pb37 or lead-free) | TQFP and sensor ICs |
| Hot air station | Reflowing solder paste on TQFP and sensors |
| Flux pen | Improving solder flow on fine-pitch pads |
| Tweezers (fine-point) | Placing 0805 components |
| Magnifying glass or microscope | Inspecting solder joints |

### Soldering Order

<Steps>
1. **The TQFP chip first,** while nothing is in the way. Put solder paste on the 32 pads. Place the ATmega328P-AU with tweezers, with its pin 1 dot at the pin 1 mark of the board. Heat it with hot air at 250-280°C from 2-3 cm above. When the paste melts, its surface tension pulls the chip into line with the pads. Check every pin with a magnifier for solder that bridges two pins.

2. **The sensors.** Solder the SHT30 and the VEML7700 with paste and hot air in the same way. The SHT30 has a metal pad under its body, which must also be soldered to its pad on the board.

3. **The regulator and the crystal.** These are larger and easier.

4. **The 0805 parts.** Melt a little solder on one pad. Hold the part with tweezers, melt that solder again and slide the part in. Then solder the other end.

5. **The USB connector.** Solder its metal shell tabs well. They take the force each time a cable is plugged in.

6. **The through-hole headers,** which are the tallest parts.

7. **The via wires,** if the board was milled.
</Steps>

### Common SMD Mistakes

<Card title="Troubleshooting" icon="warning">
- **Solder bridges two TQFP pins**: add flux and draw a clean iron tip along the pins, or soak the solder up with solder wick.
- **An 0805 part stands up on one end**: one pad melted before the other and pulled the part upright. Remove it, clean the pads and solder it again.
- **A dull, grainy joint**: the solder did not flow. Add flux and heat it again.
- **A part moved under the hot air**: use less air, or fix one end with the iron first.
</Card>

:::tip[Instrument it]
A [sensor board](/education/sensor-actuator-interfacing-stm32/) is worth building only if its readings can be trusted, and on this board that is decided by the layout. Keep the temperature sensor away from the regulator and the MCU, give each sensor its own decoupling capacitor, and keep the I2C tracks short and away from the crystal. Then the numbers it sends are ones you can [act on](https://siliconwit.io).
:::

## First Power-On and Testing

<InArticleAd />


A solder bridge here can short a USB port's 5 V to ground or put 5 V on a 3.3 V sensor. Check with a meter first, and make the first test from a USB charger, not a computer.

<Steps>
1. **Look.** Check every joint with a magnifier, the TQFP pins most of all.

2. **Measure with no power connected.** With a multimeter on continuity, check that no two of +5V, +3V3 and GND are joined.

3. **Apply power through USB.** The power LED lights. Measure 5 V at the MCU VCC pin and 3.3 V at the sensor VDD pins. If a part becomes hot, unplug at once.

4. **Test the MCU.** Connect the programmer to the ISP header and run `avrdude -c usbasp -p m328p`. If it reports the device signature, the MCU is powered and soldered correctly. This board has no LED on an output pin, so the crystal is proved only by the serial text of the program below.
</Steps>

## Firmware: Reading Sensors

<InArticleAd />


A new ATmega328P runs from its internal clock. Set the fuses for the 16 MHz crystal once, with the `avrdude` fuse command of the through-hole breakout board, or the serial text is unreadable. Then save this program as `sensor_read.c`. It reads both sensors and sends the values over UART at 9600 baud.

```c
/*
 * sensor_read.c - Read SHT30 and VEML7700 via I2C, output via UART
 * ATmega328P-AU @ 16 MHz
 */

#define F_CPU 16000000UL
#define BAUD 9600
#define UBRR_VAL ((F_CPU / 16 / BAUD) - 1)

#include <avr/io.h>
#include <util/delay.h>
#include <util/twi.h>
#include <stdio.h>

/* UART */
void uart_init(void) {
    UBRR0H = (uint8_t)(UBRR_VAL >> 8);
    UBRR0L = (uint8_t)UBRR_VAL;
    UCSR0B = (1 << TXEN0);
    UCSR0C = (1 << UCSZ01) | (1 << UCSZ00);
}

void uart_putc(char c) {
    while (!(UCSR0A & (1 << UDRE0)));
    UDR0 = c;
}

void uart_puts(const char *s) {
    while (*s) uart_putc(*s++);
}

/* I2C */
void i2c_init(void) {
    TWSR = 0;
    TWBR = ((F_CPU / 100000UL) - 16) / 2;  /* 100 kHz */
}

uint8_t i2c_start(uint8_t addr) {
    TWCR = (1 << TWINT) | (1 << TWSTA) | (1 << TWEN);
    while (!(TWCR & (1 << TWINT)));
    TWDR = addr;
    TWCR = (1 << TWINT) | (1 << TWEN);
    while (!(TWCR & (1 << TWINT)));
    return (TWSR & 0xF8);
}

void i2c_write(uint8_t data) {
    TWDR = data;
    TWCR = (1 << TWINT) | (1 << TWEN);
    while (!(TWCR & (1 << TWINT)));
}

uint8_t i2c_read_ack(void) {
    TWCR = (1 << TWINT) | (1 << TWEN) | (1 << TWEA);
    while (!(TWCR & (1 << TWINT)));
    return TWDR;
}

uint8_t i2c_read_nack(void) {
    TWCR = (1 << TWINT) | (1 << TWEN);
    while (!(TWCR & (1 << TWINT)));
    return TWDR;
}

void i2c_stop(void) {
    TWCR = (1 << TWINT) | (1 << TWSTO) | (1 << TWEN);
}

/* SHT30 (I2C address 0x44) */
void sht30_read(uint16_t *temp_raw, uint16_t *hum_raw) {
    uint8_t data[6];

    /* Send single-shot measurement command: 0x2400 (high repeatability) */
    i2c_start(0x44 << 1);
    i2c_write(0x24);
    i2c_write(0x00);
    i2c_stop();

    _delay_ms(50);  /* Wait for measurement */

    /* Read 6 bytes: temp_msb, temp_lsb, temp_crc, hum_msb, hum_lsb, hum_crc */
    i2c_start((0x44 << 1) | 1);
    for (uint8_t i = 0; i < 5; i++) data[i] = i2c_read_ack();
    data[5] = i2c_read_nack();
    i2c_stop();

    *temp_raw = ((uint16_t)data[0] << 8) | data[1];
    *hum_raw = ((uint16_t)data[3] << 8) | data[4];
}

/* VEML7700 (I2C address 0x10) */
uint16_t veml7700_read(void) {
    uint8_t low, high;

    /* Configure: ALS gain x1, integration time 100ms, power on */
    i2c_start(0x10 << 1);
    i2c_write(0x00);  /* ALS_CONF register */
    i2c_write(0x00);  /* LSB: power on, gain x1 */
    i2c_write(0x00);  /* MSB: integration 100ms */
    i2c_stop();

    _delay_ms(150);  /* Wait for measurement */

    /* Read ALS data register (0x04) */
    i2c_start(0x10 << 1);
    i2c_write(0x04);
    i2c_start((0x10 << 1) | 1);
    low = i2c_read_ack();
    high = i2c_read_nack();
    i2c_stop();

    return ((uint16_t)high << 8) | low;
}

/* Simple integer-to-string for UART output */
void print_int(int16_t val) {
    char buf[8];
    int8_t i = 0;
    if (val < 0) { uart_putc('-'); val = -val; }
    if (val == 0) { uart_putc('0'); return; }
    while (val > 0) { buf[i++] = '0' + (val % 10); val /= 10; }
    while (i > 0) uart_putc(buf[--i]);
}

int main(void) {
    uint16_t temp_raw;
    uint16_t hum_raw;
    uint16_t lux_raw;

    uart_init();
    i2c_init();

    uart_puts("Sensor Shield Ready\r\n");

    while (1) {
        /* Read SHT30 */
        sht30_read(&temp_raw, &hum_raw);
        int16_t temp_c = -45 + (175 * (int32_t)temp_raw / 65535);
        uint16_t hum_pct = 100 * (uint32_t)hum_raw / 65535;

        /* Read VEML7700 */
        lux_raw = veml7700_read();
        /* Gain x1, 100 ms: 0.0576 lux per count */
        uint16_t lux = (uint32_t)lux_raw * 576 / 10000;

        /* Output */
        uart_puts("T=");
        print_int(temp_c);
        uart_puts("C H=");
        print_int(hum_pct);
        uart_puts("% L=");
        print_int(lux);
        uart_puts(" lux\r\n");

        _delay_ms(2000);
    }
}
```
