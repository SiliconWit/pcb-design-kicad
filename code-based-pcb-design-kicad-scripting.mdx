A colleague changes one wire in a schematic and sends you the file. You open it and see nothing different, because the change is one line among hundreds on a drawing. Then a customer wants the same board with another crystal and fewer pins, and you copy the project and redraw it by hand. In this lesson you write the [ATmega328P breakout board](/education/pcb-design-kicad/atmega328p-breakout-board-through-hole/) as a Python program. A change to the circuit is then one changed line that anyone can read, and a new variant is one more call of a function. #KiCad #Python #SKiDL

## Why Code-Based PCB Design?

<Card title="Code Your Circuits" icon="star">

Until now you made every board with the mouse, in KiCad's windows and menus (its graphical user interface, GUI). A circuit written as a program gives you four things the drawing cannot:

- A readable history. Git, the tool that records each change to a file, shows a changed script line by line. A `.kicad_sch` file is text too, but a change in it is a long run of coordinates.
- Parameters. Change one value (crystal frequency, number of pins, number of LEDs) and make the whole circuit again.
- Tests. A program can check the circuit before you open KiCad, and can check 50 variants as easily as one.
- The same result every time. Anyone who runs your script gets the same list of connections.

</Card>

A script does not produce a finished board. It produces a netlist: a file that lists every part and which pins are joined. The layout still comes after it:

```text
  circuit.py        parts and connections,
    │               written with SKiDL
    ▼
  circuit.net       the netlist
    │
    │  import once in the PCB Editor
    ▼
  circuit.kicad_pcb the board file
    │
    │  pcbnew script: outline, positions
    │  you: route the tracks
    ▼
  design rules check ──► Gerber files
```

## Tools Overview

<InArticleAd />


Two Python tools do the work:

<CardGrid>
  <Card title="SKiDL" icon="open-book">
    A Python library in which you write a circuit. You name the parts and connect their pins to nets (a net is a set of pins joined together), and SKiDL writes a netlist that KiCad reads. It takes the place of the schematic editor. Install with `pip install skidl`.
  </Card>

  <Card title="KiCad pcbnew API" icon="setting">
    The Python module that comes with KiCad's PCB editor. A script can open a board file, move parts to given coordinates, draw the board outline and run the design rules check (DRC).
  </Card>
</CardGrid>

SKiDL decides what is on the board and how it is connected. pcbnew decides where each part sits. The `.net` file joins the two: the PCB Editor imports it exactly as it imports the connections of a drawn schematic.

## Building the ATmega328P Breakout in Code

<InArticleAd />


You now write the circuit of the ATmega328P breakout board (microcontroller, crystal, voltage regulator, LEDs, programming header, pin headers) as one SKiDL script, a section at a time.

Three lines carry the whole method. `Net('GND')` makes a net with a name. `Part('Device', 'R', ...)` takes the symbol `R` from the library `Device`, with a value and a footprint (the pattern of pads the part is soldered to). `r1[1] += vcc` joins pin 1 of that part to the net `vcc`: it is the wire you would draw in the schematic editor. A pin can be given by its number or by its name.

### Power Supply Section

Start with the barrel jack and the LM7805 regulator that makes 5V. The reverse-polarity diode, the screw terminal and the FTDI header of the original board are left out, to keep the script short:

```python
from skidl import *

# Use the KiCad 9 symbol libraries
set_default_tool(KICAD9)

# Power nets
vcc = Net('+5V')
gnd = Net('GND')
vin = Net('VIN')

# Barrel jack for external power (7-12V)
j1 = Part('Connector', 'Barrel_Jack_Switch', ref='J1',
          footprint='Connector_BarrelJack:BarrelJack_Horizontal')
j1[1] += vin   # Tip (positive)
j1[2] += gnd   # Sleeve (ground)
j1[3] += gnd   # Switch (tied to ground)

# LM7805 voltage regulator (TO-220)
u2 = Part('Regulator_Linear', 'LM7805_TO220', ref='U2',
          footprint='Package_TO_SOT_THT:TO-220-3_Vertical')
u2['VI'] += vin
u2['VO'] += vcc
u2['GND'] += gnd

# Input capacitor (10 uF electrolytic)
c5 = Part('Device', 'C_Polarized', value='10uF', ref='C5',
          footprint='Capacitor_THT:CP_Radial_D5.0mm_P2.50mm')
c5[1] += vin
c5[2] += gnd

# Output capacitor (10 uF electrolytic)
c6 = Part('Device', 'C_Polarized', value='10uF', ref='C6',
          footprint='Capacitor_THT:CP_Radial_D5.0mm_P2.50mm')
c6[1] += vcc
c6[2] += gnd
```

The regulator's pins are given by name (`'VI'`, `'VO'`, `'GND'`). A name cannot be confused, and a number can.

### MCU and Crystal

The microcontroller, its 16 MHz crystal with two load capacitors, and two decoupling capacitors on the supply:

```python
# ATmega328P in DIP-28
u1 = Part('MCU_Microchip_ATmega', 'ATmega328P-P', ref='U1',
          footprint='Package_DIP:DIP-28_W7.62mm')
u1['VCC'] += vcc
u1['AVCC'] += vcc
u1['GND'] += gnd   # connects both GND pins (8 and 22)

# 16 MHz crystal
xtal_net1 = Net('XTAL1')
xtal_net2 = Net('XTAL2')

y1 = Part('Device', 'Crystal', value='16MHz', ref='Y1',
          footprint='Crystal:Crystal_HC49-U_Vertical')
y1[1] += xtal_net1
y1[2] += xtal_net2

u1['XTAL1/PB6'] += xtal_net1
u1['XTAL2/PB7'] += xtal_net2

# Crystal load capacitors (22 pF each)
c1 = Part('Device', 'C', value='22pF', ref='C1',
          footprint='Capacitor_THT:C_Disc_D3.0mm_W1.6mm_P2.50mm')
c1[1] += xtal_net1
c1[2] += gnd

c2 = Part('Device', 'C', value='22pF', ref='C2',
          footprint='Capacitor_THT:C_Disc_D3.0mm_W1.6mm_P2.50mm')
c2[1] += xtal_net2
c2[2] += gnd

# Decoupling capacitors (100 nF)
c3 = Part('Device', 'C', value='100nF', ref='C3',
          footprint='Capacitor_THT:C_Disc_D3.0mm_W1.6mm_P2.50mm')
c3[1] += vcc
c3[2] += gnd

c4 = Part('Device', 'C', value='100nF', ref='C4',
          footprint='Capacitor_THT:C_Disc_D3.0mm_W1.6mm_P2.50mm')
c4[1] += vcc
c4[2] += gnd
```

### Reset Circuit

A 10 kΩ resistor holds the reset pin high, and the push button pulls it to ground. In a KiCad pin name, `~{RESET}` means the pin is active when low:

```python
# Reset pull-up resistor (10k)
reset_net = Net('RESET')

r1 = Part('Device', 'R', value='10k', ref='R1',
          footprint='Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal')
r1[1] += vcc
r1[2] += reset_net

# Reset tactile switch
sw1 = Part('Switch', 'SW_Push', ref='SW1',
           footprint='Button_Switch_THT:SW_PUSH_6mm')
sw1[1] += reset_net
sw1[2] += gnd

u1['~{RESET}/PC6'] += reset_net
```

### ISP Header

The ISP (in-system programming) header is the 2x3 connector through which a programmer writes the chip. Its pin order is a standard, so each number must go to the right signal:

```python
# 2x3 ISP programming header
j2 = Part('Connector_Generic', 'Conn_02x03_Odd_Even', ref='J2',
          footprint='Connector_PinHeader_2.54mm:PinHeader_2x03_P2.54mm_Vertical')

j2[1] += u1['PB4']    # MISO
j2[2] += vcc          # VCC
j2[3] += u1['PB5']    # SCK
j2[4] += u1['PB3']    # MOSI
j2[5] += reset_net    # RESET
j2[6] += gnd          # GND
```

### LEDs

An LED conducts in one direction only, from anode (A) to cathode (K). In KiCad's LED symbol, pin 1 is the cathode, which is the opposite of what most people expect. The script therefore uses the names `'A'` and `'K'`, not the numbers:

```python
# Power LED (green) with 330 ohm resistor
led_net1 = Net('LED_PWR')

r2 = Part('Device', 'R', value='330', ref='R2',
          footprint='Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal')
r2[1] += vcc
r2[2] += led_net1

d1 = Part('Device', 'LED', value='Green', ref='D1',
          footprint='LED_THT:LED_D3.0mm')
d1['A'] += led_net1   # Anode (pin 2 of the KiCad LED symbol)
d1['K'] += gnd        # Cathode (pin 1)

# User LED (red, on PB5/D13) with 330 ohm resistor
led_net2 = Net('LED_USER')

r3 = Part('Device', 'R', value='330', ref='R3',
          footprint='Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal')
r3[1] += u1['PB5']
r3[2] += led_net2

d2 = Part('Device', 'LED', value='Red', ref='D2',
          footprint='LED_THT:LED_D3.0mm')
d2['A'] += led_net2   # Anode
d2['K'] += gnd        # Cathode
```

### I/O Headers

Here code saves real work. A loop joins 14 header pins to 14 MCU pins in three lines, where the schematic editor needs 14 wires:

```python
# Two 1x14 female sockets exposing all I/O
j3 = Part('Connector_Generic', 'Conn_01x14', ref='J3',
          footprint='Connector_PinSocket_2.54mm:PinSocket_1x14_P2.54mm_Vertical')
j4 = Part('Connector_Generic', 'Conn_01x14', ref='J4',
          footprint='Connector_PinSocket_2.54mm:PinSocket_1x14_P2.54mm_Vertical')

# J3: Digital pins PD0-PD7, PB0-PB5
digital_pins = ['PD0','PD1','PD2','PD3','PD4','PD5','PD6','PD7',
                'PB0','PB1','PB2','PB3','PB4','PB5']
for i, pin in enumerate(digital_pins):
    j3[i + 1] += u1[pin]

# J4: Analog pins PC0-PC5, then AREF, power and reset (same order as Lesson 1)
analog_pins = ['PC0','PC1','PC2','PC3','PC4','PC5']
for i, pin in enumerate(analog_pins):
    j4[i + 1] += u1[pin]
j4[7] += u1['AREF']; j4[8] += vcc; j4[9] += reset_net
j4[10] += vin; j4[11] += vcc; j4[12] += gnd
j4[13] += vcc; j4[14] += gnd
```

### Generate the Netlist

`ERC()` is the electrical rules check. It reports pins left unconnected and outputs joined to each other. It does not know what the circuit is for, so it accepts an LED that is the wrong way round:

```python
# Run ERC (Electrical Rules Check) and generate netlist
ERC()
generate_netlist()
print("Netlist generated: atmega328p_breakout.net")
```

Put all the sections above, in the same order, into one file called `atmega328p_breakout.py`. Run it with `python atmega328p_breakout.py`. SKiDL writes a `.net` file with the same name in the current folder.

## From Netlist to PCB

<InArticleAd />


The netlist says what is connected, not where anything sits. You bring it into a board file by hand, and then place the parts by hand or by script.

### Manual Import

<Steps>

1. **Open KiCad** and create a new project.

2. **Open the PCB Editor** (pcbnew).

3. **File > Import > Netlist** and select the `.net` file that SKiDL wrote. Every footprint, connection and reference (R1, C3, U1) comes from the netlist.

4. **Place the parts** by hand.

5. **Route the tracks**, add copper pours, and run DRC as usual.

</Steps>

### Scripted Placement with pcbnew

A script can also place the parts. It needs a board file that already holds the footprints, so do steps 1 to 3 above first and save the board as `atmega328p_breakout.kicad_pcb`. The script then draws the outline and moves each part to its coordinates:

```python
"""
Basic pcbnew script to set up board outline and place components.
Run inside KiCad's scripting console or with the standalone pcbnew Python module.
"""

import pcbnew

# Load the board (or create a new one)
board = pcbnew.LoadBoard("atmega328p_breakout.kicad_pcb")

# Set board outline (66mm x 53mm, matching Lesson 1)
outline = pcbnew.PCB_SHAPE(board)
outline.SetShape(pcbnew.SHAPE_T_RECT)
outline.SetStart(pcbnew.VECTOR2I_MM(0, 0))
outline.SetEnd(pcbnew.VECTOR2I_MM(66, 53))
outline.SetLayer(pcbnew.Edge_Cuts)
outline.SetWidth(pcbnew.FromMM(0.1))
board.Add(outline)

# Place components at specific coordinates:
# (x in mm, y in mm, rotation in degrees). In KiCad, y grows downward.
placement = {
    'U1': (16.5, 31, 90),  # ATmega328P, center of board, lying along the long side
    'U2': (8, 44, 0),      # Voltage regulator, bottom left
    'J1': (15, 13, 0),     # Barrel jack, upper left edge
    'Y1': (30, 13, 0),     # Crystal, above the MCU
    'J2': (54, 11, 0),     # ISP header, top right
    'J3': (16.5, 49, 90),  # I/O socket along the bottom edge
    'J4': (16.5, 4, 90),   # I/O socket along the top edge
}

for ref, (x, y, angle) in placement.items():
    footprint = board.FindFootprintByReference(ref)
    if footprint:
        footprint.SetPosition(pcbnew.VECTOR2I_MM(x, y))
        footprint.SetOrientationDegrees(angle)

# Save the modified board
board.Save("atmega328p_breakout_placed.kicad_pcb")
print("Components placed. Open the board in KiCad to route traces.")
```

:::note
The script does not draw the tracks: KiCad's Python module has no automatic router. You route by hand in the GUI, or with an external router such as FreeRouting. What the script gives is repeatability: after a change to the netlist, run it again and every part is back at its position.
:::

## Parametric Design Example

<InArticleAd />


A function with parameters turns one circuit into a family of boards. Put the circuit inside a function, and each call with other values writes another netlist. The listing shows only the parts that change. The line with three dots stands for the MCU, supply and reset code you wrote above:

```python
from skidl import *

def make_breakout(crystal_freq='16MHz', num_io_pins=14, led_count=2,
                  board_name='atmega328p_breakout'):
    """Generate a breakout board netlist with configurable parameters."""
    default_circuit.reset()

    vcc, gnd, vin = Net('+5V'), Net('GND'), Net('VIN')
    reset_net = Net('RESET')

    # ... (MCU, power supply, reset circuit same as before) ...

    # Crystal with parametric frequency and matching load caps
    xtal1, xtal2 = Net('XTAL1'), Net('XTAL2')
    y1 = Part('Device', 'Crystal', value=crystal_freq,
              footprint='Crystal:Crystal_HC49-U_Vertical')
    y1[1] += xtal1; y1[2] += xtal2

    load_cap_values = {'8MHz': '15pF', '16MHz': '22pF', '20MHz': '18pF'}
    cap_val = load_cap_values.get(crystal_freq, '22pF')

    for net in [xtal1, xtal2]:
        c = Part('Device', 'C', value=cap_val,
                 footprint='Capacitor_THT:C_Disc_D3.0mm_W1.6mm_P2.50mm')
        c[1] += net; c[2] += gnd

    # Parametric LEDs (1 to 4)
    led_colors = ['Green', 'Red', 'Yellow', 'Blue']
    led_pins = [None, 'PB5', 'PB4', 'PB3']
    for i in range(min(led_count, 4)):
        led_net = Net(f'LED_{i}')
        r = Part('Device', 'R', value='330',
                 footprint='Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal')
        d = Part('Device', 'LED', value=led_colors[i],
                 footprint='LED_THT:LED_D3.0mm')
        r[1] += vcc if i == 0 else u1[led_pins[i]]
        r[2] += led_net; d['A'] += led_net; d['K'] += gnd

    # Parametric I/O header (variable pin count)
    digital_pins = ['PD0','PD1','PD2','PD3','PD4','PD5','PD6','PD7',
                    'PB0','PB1','PB2','PB3','PB4','PB5']
    pin_count = min(num_io_pins, 14)
    j3 = Part('Connector_Generic', f'Conn_01x{pin_count:02d}',
              footprint=f'Connector_PinHeader_2.54mm:PinHeader_1x{pin_count:02d}_P2.54mm_Vertical')
    for p in range(pin_count):
        j3[p + 1] += u1[digital_pins[p]]

    ERC()
    generate_netlist(file_=f'{board_name}.net')
    print(f"Generated {board_name}.net: {crystal_freq}, {pin_count} I/O pins, {led_count} LEDs")

# Generate three variants from one function
make_breakout('16MHz', 14, 2, 'breakout_full')
make_breakout('8MHz',   8, 1, 'breakout_minimal')
make_breakout('20MHz', 14, 4, 'breakout_extended')
```

Three calls give three netlist files. `breakout_minimal` has an 8 MHz crystal with 15 pF load capacitors, one power LED and 8 I/O pins. `breakout_extended` runs at 20 MHz with four LEDs.

Read the table of capacitor values with care. The right load capacitor comes from the crystal's data sheet, not from its frequency. For a frequency that is not in the table, the function uses 22 pF and gives no warning. A function that guesses in silence is the main risk of parametric design: make yours stop with an error.

## Automated DRC with Python

<InArticleAd />


The design rules check (DRC) compares a layout with the rules of the factory and with the netlist: clearances, track widths, nets left unconnected. A script can run it on every board file with no window open:

```python
"""
Run DRC on a KiCad PCB file and report results.
Requires KiCad's pcbnew Python module.
"""

import pcbnew

def run_drc(pcb_path, report_path="drc_report.txt"):
    """Run DRC on a board file and return pass/fail with details."""
    board = pcbnew.LoadBoard(pcb_path)

    # Run all DRC checks and write the results to a text report
    pcbnew.WriteDRCReport(board, report_path, pcbnew.EDA_UNITS_MM, True)

    # Collect violations: each one starts with a line like "[clearance]: ..."
    with open(report_path) as f:
        violations = [line.strip() for line in f if line.startswith('[')]

    # Report
    if not violations:
        print(f"DRC PASSED: {pcb_path}")
        print("No violations found.")
        return True
    else:
        print(f"DRC FAILED: {pcb_path}")
        print(f"Found {len(violations)} violation(s):")
        for i, v in enumerate(violations, 1):
            print(f"  {i}. {v}")
        print(f"Full details are in {report_path}")
        return False

# Example usage
passed = run_drc("atmega328p_breakout_placed.kicad_pcb")
if not passed:
    exit(1)  # Fail the CI pipeline
```

The last line returns an error code when DRC fails. A continuous integration (CI) service, such as GitHub Actions, runs a script like this on a server each time you send a change, and marks the change as failed on that code. A clearance error is then found on the day it is made, not when the boards arrive.

## KiCad Action Plugins

<InArticleAd />


A Python script can also add a command to KiCad's own menus. This small plugin writes the board name, revision and date in the printed text of the board (the silkscreen layer):

```python
"""
KiCad Action Plugin: Add Board Info Text
Place this file in KiCad's scripting/plugins directory.

Linux:   ~/.local/share/kicad/9.0/scripting/plugins/
macOS:   ~/Documents/KiCad/9.0/scripting/plugins/
Windows: Documents/KiCad/9.0/scripting/plugins/
"""

import pcbnew
import datetime

class BoardInfoPlugin(pcbnew.ActionPlugin):
    def defaults(self):
        self.name = "Add Board Info"
        self.category = "Fabrication"
        self.description = "Stamps revision, date, and board name on silkscreen"
        self.show_toolbar_button = True

    def Run(self):
        board = pcbnew.GetBoard()
        board_name = board.GetFileName().split('/')[-1].replace('.kicad_pcb', '')
        date_str = datetime.date.today().isoformat()
        info_text = f"{board_name}  Rev 1.0  {date_str}"

        # Create text item on front silkscreen
        txt = pcbnew.PCB_TEXT(board)
        txt.SetText(info_text)
        txt.SetPosition(pcbnew.VECTOR2I_MM(45, 44))  # Lower right, above J3
        txt.SetLayer(pcbnew.F_SilkS)
        txt.SetTextSize(pcbnew.VECTOR2I_MM(1, 1))
        txt.SetTextThickness(pcbnew.FromMM(0.15))

        board.Add(txt)
        pcbnew.Refresh()
        print(f"Added board info: {info_text}")

BoardInfoPlugin().register()
```

Put the file in the plugins folder and restart KiCad. The plugin appears under **Tools, External Plugins**, and one click adds the text.

## Limitations and the Road Ahead

<InArticleAd />


Code replaces part of the GUI, not all of it. The circuit, its variants and its checks work well as code today. Four things do not:

- SKiDL writes a netlist, not a drawing. Nobody can understand the circuit at a glance, as from a schematic.
- Placement by script suits simple boards. A dense board still needs placement by hand, and routing by hand is faster for most boards.
- The pcbnew module changes between KiCad versions. A script written for KiCad 9 may need changes after an upgrade.
- No check knows your intent. A script that runs with no errors, and passes ERC and DRC, can still describe a wrong circuit: a reversed LED, a wrong capacitor value. Review the script as you would a schematic. On the assembled board, check for shorts and polarity with a meter before first power.

**The practical workflow:**
Write the circuit in Python with SKiDL, then do the layout in KiCad's GUI.

<Card title="Course Summary: PCB Design with KiCad" icon="star">

**In this lesson** you wrote a circuit with SKiDL, made variants from one function, ran DRC by script, wrote a KiCad plugin, and learned where code helps and where the GUI is better.

**In the course** you went from through-hole parts on two layers to four-layer boards with USB, radio, batteries and motors: the cycle of schematic, ERC, layout, DRC and Gerber files, then factory orders, planes, differential pairs, antennas, QFN packages and high currents.

</Card>

:::tip[Course Complete]
You can now take a circuit from an idea to files a factory can build, by drawing or by code. For enclosures and mechanical parts for your boards, see the [Code-Based Mechanical Design](/education/code-based-mechanical-design/) course.
:::
