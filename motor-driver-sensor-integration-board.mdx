A robot's motion sensor reads correctly on the bench, and reads nonsense when the motors start. The sensor is not faulty. The motors take large, sudden currents, and on a careless board those currents disturb the small signals beside them. In this lesson you design one board that carries both: a DRV8833 driver for two motors and an MPU6050 motion sensor. You learn to place and route them so that neither disturbs the other, and to protect the board against a supply connected backwards. #KiCad #MotorDriver #IMU

The plan of the board: motor parts on one side, sensor parts on the other, and the two grounds joined at one place only.

```text
  ┌──────────────────────┬──────┬─────────────────────┐
  │ MOTOR ZONE           │ gap  │ SENSOR ZONE         │
  │ large sudden current │      │ small quiet signals │
  │ ┌─────────┐          │ only │         ┌─────────┐ │
  │ │ DRV8833 ├──► motor │ gro- │  I2C ◄──┤ MPU6050 │ │
  │ │ driver  ├──► motor │ und  │         │ sensor  │ │
  │ └────┬────┘          │      │         └─────────┘ │
  │   supply screws      │      │ own 3.3 V regulator │
  │   wide traces        │      │ thin traces         │
  ├──────────────────────┴──────┴─────────────────────┤
  │ MCU header: the two grounds join near here, once  │
  └───────────────────────────────────────────────────┘
```

## What We Are Building

<Card title="Motor Driver and Sensor Integration Board" icon="star">
A compact expansion board that plugs onto a microcontroller (MCU) development board through a 2x10 pin header. It drives two DC motors (or one stepper) through a DRV8833 H-bridge, reads motion data from an MPU6050 over I2C, and measures motor current with shunt resistors and an MCP6001 op-amp. Screw terminals hold the motor and power wires. Protection parts guard against a reversed supply and against voltage spikes from the motors.
</Card>

Four terms:

- An H-bridge is four electronic switches around a motor. Closed in pairs, they send current through the motor in either direction.
- An IMU (inertial measurement unit) senses motion: acceleration and rate of turn, on three axes each.
- A shunt is a resistor of very low value in the path of a current. The small voltage across it tells you the current.
- PWM (pulse width modulation) switches a pin on and off quickly. The fraction of time it is on sets the motor speed.

## Mixed-Signal PCB Design Principles

<InArticleAd />


A mixed-signal board carries power and small signals together. The difficulty is that copper is not a perfect conductor. A motor current of 1.5 A in a thin ground trace of 0.05 ohm makes 75 mV across that trace. If the sensor uses the same trace as its ground, its "0 V" moves by 75 mV each time the motor starts, and the readings move with it. A motor also makes voltage spikes when its current is switched off.

So treat the board as two zones. The motor zone (left half) carries high current, tolerates noise and needs traces 1 mm wide or more. The signal zone (right half) carries millivolt signals and I2C (a two-wire data bus) and needs a clean supply. The two grounds join at a single chosen point, called a star ground: a quiet side street joined to the main road at one junction, so that no lorry uses it as a short cut. The comparison has a limit. Current takes every path open to it, so the layout must make the motor's own path the easy one: screw terminals close to the driver, and a 100 nF capacitor within 3 mm of each supply pin.

## DRV8833 Motor Driver

<InArticleAd />


A microcontroller pin gives a few milliamperes, and a motor needs a thousand times more. The driver stands between them and switches the motor supply as the MCU commands. The DRV8833 from Texas Instruments holds two H-bridges, each rated for 1.5A continuous (2A peak), with a motor supply from 2.7V to 10.8V. A 12V supply is too high for it. The HTSSOP-16 package has a metal pad underneath that carries heat out of the chip.

### Pinout and Functionality

Each H-bridge (channel A and channel B) is controlled by two PWM input pins:

| Pin | Function | Connection |
|-----|----------|------------|
| AIN1, AIN2 | Channel A PWM inputs | MCU PWM outputs |
| BIN1, BIN2 | Channel B PWM inputs | MCU PWM outputs |
| AOUT1, AOUT2 | Channel A motor outputs | Motor A screw terminal |
| BOUT1, BOUT2 | Channel B motor outputs | Motor B screw terminal |
| VM | Motor supply voltage | External power (2.7V to 10.8V) |
| VINT | Internal 3.3V regulator bypass | 2.2 uF capacitor to GND (the DRV8833 has no separate logic supply pin) |
| VCP | Charge pump | 10 nF capacitor to VM |
| AISEN, BISEN | Bridge A and bridge B ground returns | Through the shunt resistors to GND |
| GND | Ground (multiple pins) | Ground plane |
| nSLEEP | Sleep control (active low) | Pull high through 10k for always-on, or connect to MCU GPIO |
| nFAULT | Fault output (open drain) | Pull high through 10k, connect to MCU GPIO |
| Exposed pad | Thermal pad | Solder to ground, thermal vias to back copper |

With PWM on one input and the other input low, the motor runs at a variable speed in one direction. Put the PWM on the other input and it reverses.

### Thermal Management

The switches inside the DRV8833 have resistance, so the motor current heats them. The current passes through two switches in series, with a combined on-resistance, written RDS(on), of about 0.36 ohm. The heat in one channel at 1.5A is:

$$P = I^2 R = 1.5^2 \times 0.36 = 0.81\,\text{W}$$

With both channels loaded the total is about 1.6W, too much for a package this small to lose to the air. The board must carry the heat away through the pad.

<Steps>

1. **Solder the exposed pad** to a large copper area on the top layer. The pad is the main path for heat out of the chip.

2. **Place thermal vias** (plated holes, 0.3mm drill, in a 3x3 or 4x4 array) under the pad, to carry the heat to the bottom layer.

3. **Add a copper pour on the bottom layer** under the DRV8833, to spread the heat and pass it to the air.

4. **Connect the pad to GND.** It is joined to ground inside the DRV8833, so this copper is also part of the ground.

</Steps>

### Sleep and Fault Pins

The "n" before a pin name means the pin is active when it is low.

- nSLEEP low puts the driver to sleep, where it takes a few microamperes. A 10 kohm pull-up holds it high, so the driver is awake by default. Route it to a GPIO pin if the MCU must switch the driver off.
- nFAULT goes low when the driver detects too much current or heat. It is an open-drain output: it can pull the line low but cannot drive it high, so it needs a 10 kohm pull-up. Connect it to an MCU interrupt pin, so the firmware stops the motors at once.

## MPU6050 IMU

<InArticleAd />


The MPU6050 holds a 3-axis accelerometer and a 3-axis gyroscope in one QFN-24 package, and sends its readings over I2C at up to 400 kHz. The accelerometer range can be set from 2g to 16g, and the gyroscope from 250 to 2000 degrees per second, each in both directions.

### I2C Interface

I2C uses two lines, SDA for data and SCL for the clock. No device drives these lines high: a pull-up resistor on each line (10 kohm to 3.3V here) does that. The AD0 pin selects the I2C address: GND for 0x68, or VCC for 0x69, so two MPU6050s can share one bus.

The INT pin tells the MCU that a new reading is ready, so the MCU reads at a steady rate without asking repeatedly.

### Placement Considerations

The sensing parts inside the MPU6050 are tiny moving masses, so the chip also feels vibration and bending of the board itself:

- Place it near the center of the board, where the board bends least
- Put it close to the center of rotation if the board sits on a turning platform
- Keep it away from the motor driver and from the board edge, where vibration is larger
- Use solid ground copper under it

### Decoupling

A decoupling capacitor is a small store of charge beside a supply pin. It supplies the short bursts of current the chip takes, so the voltage at the pin stays steady. The MPU6050 has two supply pins:

- VDD: 100 nF ceramic and 10 nF ceramic, within 2 mm of the pin
- VLOGIC, which sets the voltage of the I2C lines: 100 nF ceramic close to the pin, connected to 3.3V

Give the MPU6050 its own 3.3V trace from the LDO (the regulator), not one shared with motor power.

## Current Sensing

<InArticleAd />


A stalled (blocked) motor takes several times its normal current, which can burn the motor or strip a gear. Firmware that reads the current can stop in time. This board uses low-side current sensing: a shunt resistor sits between the driver's ground return pin and ground, so the voltage across it is measured from ground and is proportional to the motor current.

### Shunt Resistor Selection

A larger shunt gives a larger signal, but it wastes more power and takes voltage from the motor. The shunt resistors are 0.1 ohm in a 2512 package, rated for 1W. At the maximum motor current of 1.5A:

| Parameter | Formula | Value |
|-----------|---------|-------|
| Voltage drop | $V = I R$ | $1.5\,\text{A} \times 0.1\,\Omega = 150\,\text{mV}$ |
| Power dissipation | $P = I^2 R$ | $1.5^2 \times 0.1 = 0.225\,\text{W}$ |
| Package rating | | 1W (4.4x safety margin) |

The MCU reads a voltage with its ADC (analog to digital converter), which divides its range into steps. A 10-bit ADC with a 3.3V reference has steps of 3.2 mV, so 150 mV covers only about 47 steps: too coarse. An op-amp (an amplifier chip) makes the signal larger first.

### Op-Amp Amplifier

The MCP6001 is connected as a non-inverting amplifier: the output has the same sign as the input, and two resistors set the gain to 10, so the full 1.5A gives 1.5V, about 465 steps:

| Parameter | Value |
|-----------|-------|
| Configuration | Non-inverting |
| Feedback resistor (R_f) | 9 kohm |
| Input resistor (R_in) | 1 kohm |
| Gain | $1 + R_f / R_{in} = 1 + 9 = 10$ |
| Output at 1.5A | 150 mV x 10 = 1.5V |
| Output at 0.5A | 50 mV x 10 = 0.5V |

The MCP6001 works from a single 3.3V or 5V supply, and its input and output can go down to 0 V, which a signal measured from ground needs. A 10 nF capacitor on its output smooths the PWM ripple before the ADC pin.

Each bridge has its own shunt, but the single MCP6001 amplifies only one of them (motor A, on AISEN). To measure motor B as well, add a second op-amp stage on BISEN. The DRV8833 also uses these pins for its own current limit, which acts when a sense pin reaches 200 mV: with 0.1 ohm shunts that is 2 A.

## Protection Circuits

<InArticleAd />


:::caution[Two supplies, one ground]
The motor supply (VM) and the 5V of the MCU board are joined only at ground. Never connect VM to the 5V pin: a motor supply on the 5V line of a board plugged into a computer pushes current back into the USB port and can damage it. The motor supply is a battery or a low-voltage adapter. No mains voltage is used on this board.
:::

### Reverse Polarity Protection

Two wires in a screw terminal are easy to swap, and a reversed supply destroys the driver at once. A P-channel MOSFET (SI2301) in the positive line is a switch that closes only when the supply is the right way round.

```text
  J4 (+) ──► drain ──[ Q1 ]── source ──► VM (to DRV8833)
                       │
                      gate
                       │
  J4 (-) ──────────────┴───────────────► GND
```

A MOSFET contains a diode between drain and source, called the body diode. With the supply the right way round, current first passes through this diode and VM rises. The gate, at 0 V, is now far below the source, which switches a P-channel MOSFET fully on. The loss is small: about 0.15 V at 1.5 A through the SI2301's on-resistance of about 0.1 ohm. With the supply reversed, the gate is not below the source, the MOSFET stays off, and the body diode points against the current. With drain and source exchanged, the body diode would pass a reversed supply straight into the driver.

<Steps>

1. **Connect the drain** of the P-MOSFET to the positive terminal of the power input screw terminal.

2. **Connect the source** to the VM net that feeds the DRV8833 and bulk capacitor.

3. **Connect the gate** to the ground side of the power input. V_GS is the gate voltage measured from the source: negative with the supply the right way round (on), zero or positive when reversed (off).

</Steps>

The SI2301 allows at most 8 V between gate and source, and here that voltage equals the supply. Above 8 V, use a P-MOSFET with a 20 V gate rating.

### TVS Diode

A motor that is switched off or slowed quickly sends a short voltage spike into its supply. A TVS (transient voltage suppressor) diode does nothing at normal voltage and conducts strongly above its threshold, so it takes the energy of the spike. The SMBJ12A begins to conduct at about 13.3 V, which is above the 11.8V absolute maximum of the DRV8833's VM pin. It limits the damage of a large spike but does not make every spike safe.

Place the TVS diode across the motor power input, after the reverse polarity MOSFET and before the DRV8833.

### Flyback Diodes

A motor winding is a coil, and the current in a coil cannot stop at once. When a switch in the H-bridge opens, the current needs another path, or it makes a high voltage. A flyback diode is that path. The DRV8833 has such diodes inside. External ones (SS14 Schottky) are optional and take stress off the driver. Place them close to the screw terminals, one from each motor output to VM, with the anode on the output and the cathode on VM. Do not place a diode directly across the two terminals of a motor that runs in both directions: it would short the driver in one direction.

### Bulk Capacitor

When a motor starts or reverses, it takes a large current for a moment, and long supply wires cannot deliver it quickly. A 100 uF electrolytic capacitor on the motor power input is a local store that supplies this current and absorbs part of each spike. Place it as close to the DRV8833 as possible, with short, wide traces.

## PCB Layout

<InArticleAd />


On a 2-layer board, three tools keep motor noise away from the IMU: distance between the zones, ground copper over the free space, and trace widths chosen for the current.

### Board Outline and Zones

<Steps>

1. **Set the board outline** to 50 x 45 mm. Place M3 mounting holes (3.2 mm drill) at each corner, 3 mm in from the edges, for spacers that hold the board above the MCU board.

2. **Divide the board in your plan** into two halves. The left half is the motor zone: DRV8833, screw terminals, bulk capacitor, protection circuits, shunt resistors. The right half is the signal zone: MPU6050, LDO, I2C pull-ups.

3. **Place the MCU header** along the bottom edge, across both zones. Signals cross from one zone to the other here, and the star ground point is close to it.

</Steps>

### Component Placement

| Component | Placement | Rationale |
|-----------|-----------|-----------|
| DRV8833 (U1) | Center-left | Close to screw terminals, away from IMU |
| Screw terminals (J2, J3, J4) | Left edge | Easy access, short motor traces |
| Bulk cap (C1) | Next to DRV8833 | Minimize loop area for transient current |
| TVS diode (D1) | Near J4 | Clamp spikes at the source |
| P-MOSFET (Q1) | Between J4 and C1 | First component in the power path |
| Shunt resistors (R1, R2) | Below DRV8833 | In the ground return path |
| MCP6001 (U3) | Between DRV8833 and MPU6050 | Close to shunts, output routed to header |
| MPU6050 (U2) | Center-right | Away from motor traces and screw terminals |
| AMS1117-3.3 (U4) | Near MPU6050 | Clean 3.3V supply, short trace to IMU |
| MCU header (J1) | Bottom edge | Stacks onto dev board below |

### Trace Width and Routing

A trace that is too narrow for its current runs hot and loses voltage, so the width follows the current. For standard board copper (called 1 oz, 0.035 mm thick):

| Trace Type | Width | Current | Notes |
|------------|-------|---------|-------|
| Motor power (VM) | 1.5 mm | Up to 3A (both channels) | Keep short, use copper pour where possible |
| Motor outputs | 1.0 mm | Up to 1.5A per channel | DRV8833 to screw terminals |
| Ground return | 1.0 mm or pour | Up to 3A | Use copper pour on bottom layer |
| I2C (SDA, SCL) | 0.2 mm | < 1 mA | Keep away from motor traces |
| PWM signals | 0.2 mm | < 1 mA | Route on opposite side from I2C |
| Analog (ISENSE) | 0.2 mm | < 1 mA | Guard with ground traces on both sides |

### Thermal Via Array

Place the thermal vias under the DRV8833 pad as a 4 x 4 array (16 vias, 0.3 mm drill, 0.6 mm pad), all joined to the copper pour on the bottom layer. Cover (tent) them with solder mask on the bottom side, so that solder does not run down the holes.

### Ground Plane Strategy

A ground pour is copper that fills the free space of a layer and is connected to GND. On a 2-layer board, signal traces break it up, so plan where the currents will flow:

<Steps>

1. Fill the bottom layer with a ground pour. This is the main ground and it also spreads heat.

2. **Think of the pour as two parts:** motor ground (left half) and signal ground (right half). Do not cut the copper. The placement of the parts decides where the current flows: each current returns by the shortest path to its own source.

3. **Join the two parts** at a single point near the bulk capacitor and the MCU header GND pins. This is the star ground point. Motor current returns through the left side of the pour to the negative terminal of J4, and signal current returns on the right side to the header GND.

4. **Add ground vias** around the MPU6050 and between the two zones, to join the top and bottom ground pours.

5. **Top layer ground pour:** Fill the free space of the top layer with ground copper, most of all around the MPU6050, as a shield against motor noise.

</Steps>

### Design Rule Check

Before you make the manufacturing files, run the DRC (design rules check) in KiCad. It compares the board with the limits of the factory:

- Minimum trace width: 0.15 mm (for signal traces)
- Minimum clearance: 0.15 mm
- Minimum via drill: 0.3 mm
- Thermal relief on all pads connecting to copper pours
- No unrouted nets
- No overlapping pads or silk

:::tip[Instrument it]
This board is itself an instrument: it drives a motor and [senses what the motor is doing](/education/sensor-actuator-interfacing-stm32/). Keep the shunt and its amplifier close to the driver, so that a stall shows clearly as a rise in current, and keep the IMU away from the high-current traces. Such a board can [stream](/education/iot-systems/) load and motion to a [dashboard](https://siliconwit.io). The decision to stop a stalled motor stays in the firmware on the board, where it is fast.
:::

## Assembly Notes

<InArticleAd />


<Steps>

1. Solder the two fine-pitch chips first. The DRV8833 (HTSSOP-16 with exposed pad) and MPU6050 (QFN-24) have pads underneath that an iron cannot reach. Apply solder paste with a stencil and melt it with a hot air station or a reflow oven.

2. Solder the small SMD passives next. Capacitors, resistors, and the SOT-23-5 op-amp can be soldered by hand or with the chips.

3. Solder the SOT-223 LDO. Its large tab carries heat into the board, so give it a full joint.

4. Fit the through-hole parts last. Solder the screw terminals and pin headers from the bottom side, with the headers plugged into the MCU board so the pins stay straight.

5. **Test without motors.** Power the board through the MCU header (5V and GND) and measure 3.3V at the LDO output. Check that nSLEEP is high. Then check the motor supply's voltage and polarity with a meter and connect it to J4. Send PWM signals and look at the motor outputs with an oscilloscope or logic analyzer.

6. Connect the motors and test. Start with a low PWM duty cycle and raise it slowly. Watch the current sense output, and check that the MPU6050 answers on I2C (address 0x68).

</Steps>

## Firmware: Motor Control with IMU Feedback

<InArticleAd />


The sketch below starts the MPU6050 over I2C and reads the acceleration. A proportional controller then drives the motors: the more the board tilts, the faster they turn. It also reads the current sense voltage and prints all values to the serial monitor.

It works with any MCU board that the Arduino software supports. Change the pin numbers to match your header wiring, and set `ADC_REF` and `ADC_RESOLUTION` to the reference voltage and the number of steps of your MCU's ADC.

```cpp
// Motor Driver + IMU Integration Board - Basic Control Sketch
// Drives two DC motors proportionally to board tilt using MPU6050 data

#include <Wire.h>

// Pin definitions (match MCU header assignments)
const int PWM1_PIN = 3;   // AIN1 - Motor A forward
const int PWM2_PIN = 5;   // AIN2 - Motor A reverse
const int PWM3_PIN = 6;   // BIN1 - Motor B forward
const int PWM4_PIN = 9;   // BIN2 - Motor B reverse
const int ISENSE_PIN = A0; // Current sense analog input
const int FAULT_PIN = 2;   // nFAULT (interrupt capable)
const int SLEEP_PIN = 4;   // nSLEEP

// MPU6050 I2C address (AD0 = GND)
const uint8_t MPU_ADDR = 0x68;

// Current sense calibration
const float SHUNT_RESISTANCE = 0.1;  // ohms
const float AMP_GAIN = 10.0;         // op-amp gain
const float ADC_REF = 5.0;           // ADC reference voltage
const int ADC_RESOLUTION = 1024;     // 10-bit ADC

// Motor control
const int MAX_SPEED = 200;           // max PWM value (0 to 255)
const float TILT_THRESHOLD = 0.05;   // minimum tilt to start motors (g)
const float TILT_SCALE = 2.0;        // proportional gain

// Variables
int16_t accelX, accelY, accelZ;
int16_t gyroX, gyroY, gyroZ;
volatile bool motorFault = false;

void setup() {
  Serial.begin(115200);
  Wire.begin();

  // Configure motor pins
  pinMode(PWM1_PIN, OUTPUT);
  pinMode(PWM2_PIN, OUTPUT);
  pinMode(PWM3_PIN, OUTPUT);
  pinMode(PWM4_PIN, OUTPUT);

  // Configure control pins
  pinMode(SLEEP_PIN, OUTPUT);
  pinMode(FAULT_PIN, INPUT_PULLUP);

  // Enable motor driver
  digitalWrite(SLEEP_PIN, HIGH);

  // Attach fault interrupt
  attachInterrupt(digitalPinToInterrupt(FAULT_PIN), faultISR, FALLING);

  // Initialize MPU6050
  initMPU6050();

  Serial.println("Motor Driver + IMU Board Ready");
  Serial.println("Tilt the board to drive motors");
  Serial.println("accelX, accelY, accelZ, motorA, motorB, current_mA");
}

void loop() {
  // Check for motor fault
  if (motorFault) {
    stopMotors();
    Serial.println("MOTOR FAULT DETECTED - motors stopped");
    delay(1000);
    motorFault = false;
    return;
  }

  // Read MPU6050
  readMPU6050();

  // Convert raw accelerometer to g (default range: +/- 2g, sensitivity 16384 LSB/g)
  float ax = accelX / 16384.0;
  float ay = accelY / 16384.0;

  // Calculate motor speeds from tilt
  int motorA = 0;
  int motorB = 0;

  // Forward/backward tilt (X axis) drives both motors equally
  if (abs(ax) > TILT_THRESHOLD) {
    int speed = constrain(abs(ax) * TILT_SCALE * MAX_SPEED, 0, MAX_SPEED);
    motorA = (ax > 0) ? speed : -speed;
    motorB = (ax > 0) ? speed : -speed;
  }

  // Left/right tilt (Y axis) creates differential steering
  if (abs(ay) > TILT_THRESHOLD) {
    int diff = constrain(abs(ay) * TILT_SCALE * MAX_SPEED, 0, MAX_SPEED / 2);
    if (ay > 0) {
      motorA += diff;
      motorB -= diff;
    } else {
      motorA -= diff;
      motorB += diff;
    }
  }

  // Clamp motor values
  motorA = constrain(motorA, -MAX_SPEED, MAX_SPEED);
  motorB = constrain(motorB, -MAX_SPEED, MAX_SPEED);

  // Drive motors
  driveMotor(PWM1_PIN, PWM2_PIN, motorA);
  driveMotor(PWM3_PIN, PWM4_PIN, motorB);

  // Read current
  float current_mA = readCurrent();

  // Print data
  Serial.print(ax, 2); Serial.print(", ");
  Serial.print(ay, 2); Serial.print(", ");
  Serial.print(accelZ / 16384.0, 2); Serial.print(", ");
  Serial.print(motorA); Serial.print(", ");
  Serial.print(motorB); Serial.print(", ");
  Serial.println(current_mA, 1);

  delay(20); // 50 Hz update rate
}

void initMPU6050() {
  // Wake up MPU6050 (clear sleep bit)
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x6B); // PWR_MGMT_1 register
  Wire.write(0x00); // Clear sleep bit
  Wire.endTransmission(true);
  delay(100);

  // Set accelerometer range to +/- 2g
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x1C); // ACCEL_CONFIG register
  Wire.write(0x00); // +/- 2g
  Wire.endTransmission(true);

  // Set gyroscope range to +/- 250 deg/s
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x1B); // GYRO_CONFIG register
  Wire.write(0x00); // +/- 250 deg/s
  Wire.endTransmission(true);

  // Set digital low-pass filter to 44 Hz
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x1A); // CONFIG register
  Wire.write(0x03); // DLPF_CFG = 3 (44 Hz accel, 42 Hz gyro)
  Wire.endTransmission(true);
}

void readMPU6050() {
  Wire.beginTransmission(MPU_ADDR);
  Wire.write(0x3B); // Start at ACCEL_XOUT_H
  Wire.endTransmission(false);
  Wire.requestFrom(MPU_ADDR, (uint8_t)14, (uint8_t)true);

  accelX = (Wire.read() << 8) | Wire.read();
  accelY = (Wire.read() << 8) | Wire.read();
  accelZ = (Wire.read() << 8) | Wire.read();
  Wire.read(); Wire.read(); // Skip temperature
  gyroX  = (Wire.read() << 8) | Wire.read();
  gyroY  = (Wire.read() << 8) | Wire.read();
  gyroZ  = (Wire.read() << 8) | Wire.read();
}

void driveMotor(int pin1, int pin2, int speed) {
  if (speed > 0) {
    analogWrite(pin1, speed);
    analogWrite(pin2, 0);
  } else if (speed < 0) {
    analogWrite(pin1, 0);
    analogWrite(pin2, -speed);
  } else {
    analogWrite(pin1, 0);
    analogWrite(pin2, 0);
  }
}

float readCurrent() {
  int raw = analogRead(ISENSE_PIN);
  float voltage = (raw * ADC_REF) / ADC_RESOLUTION;
  float shuntVoltage = voltage / AMP_GAIN;
  float current = shuntVoltage / SHUNT_RESISTANCE;
  return current * 1000.0; // return milliamps
}

void stopMotors() {
  analogWrite(PWM1_PIN, 0);
  analogWrite(PWM2_PIN, 0);
  analogWrite(PWM3_PIN, 0);
  analogWrite(PWM4_PIN, 0);
}

void faultISR() {
  motorFault = true;
}
```

<Card title="Motor Driver Board Summary" icon="star">

- Mixed-signal layout: a motor zone and a sensor zone on one 2-layer board, with the two grounds joined at one point and trace widths chosen for the current
- Motor driver (DRV8833): a dual H-bridge, with its heat carried away through the pad, a via array and bottom copper
- Sensor (MPU6050): an IMU placed and decoupled away from the motor circuits, on I2C with pull-ups
- Current sensing: a low-side shunt and an op-amp that make a signal the ADC can read
- Protection: a P-MOSFET against a reversed supply (drain to the input, source to the load), a TVS diode and a bulk capacitor against spikes and dips, and flyback diodes from each motor output to the supply
